> 目标：在微信小程序「避雷真」（网购避雷 / 店铺避坑查询）可能被下架之前，把它的全量数据完整保存到 GitHub。
>
> **当前状态：仓库已建立，自动解密 + 接口提取 + 全量翻页抓取的链路已就位；原始业务数据尚未接入。**
> 原因、已做过的排查和确切结论见 [STATUS.md](STATUS.md)，需要人工配合的一步见 [拿数据指引.md](拿数据指引.md)。

## 为什么要建这个仓库

内容托管在国内小程序平台上，一旦被下架，小程序里的数据会随服务端一起消失，且没有网页快照、没有搜索引擎缓存、没有第三方存档。本仓库用于保存一份**可离线阅读、可校验、可复现**的独立副本。

## 数据边界（重要）

- 本仓库只做资料性存档备份，数据版权归原小程序 / 原作者所有，**并非官方数据源**。
- 只抓取小程序自身公开可访问的数据接口，**不绕过登录鉴权、不采集用户个人信息、不请求非公开管理接口**。
- 抓取带限速与失败重试，避免对原服务造成压力。
- 如原作者或权利方要求下线，请通过 GitHub Issue 联系仓库所有者，会及时处理。

## 目录结构

| 路径 | 内容 |
| --- | --- |
| `data/` | 全量原始数据：每页原始响应 + 汇总 JSONL + `meta.json` |
| `snapshots/` | 页面 / 截图快照（如有） |
| `tools/decrypt_scan.cjs` | 解密电脑微信小程序包（V1MMWX），提取 appid、后端域名、关键词命中 |
| `tools/fetch_api.py` | 拿到接口后一键翻页全量抓取，落盘到 `data/` |
| `STATUS.md` | 进度、已完成侦察、当前阻塞点 |
| `拿数据指引.md` | 需要人工配合的 30 秒操作 |
| `CHANGELOG.md` / `PITFALLS.md` | 改动记账 / 踩坑记录 |

## 三步跑数据

1. 按 [拿数据指引.md](拿数据指引.md) 让本机留下该小程序的代码包（或提供一次抓包 / 后台导出文件）。
2. `node tools/decrypt_scan.cjs` 找出该小程序的 appid 与后端域名、接口路径。
3. `python tools/fetch_api.py --url "https://<域名>/<接口>?page={page}" --end 200 --out data/` 全量抓取并入库。

> 仓库为公开存档，便于被 fork 形成多份副本；如需改为私有，可在仓库设置里切换。
